# Several GPUs behind one hotkey

**Needs miner release 1.2.0rc8 or later (mechanism v2).** Older miner images ignore the URL list and would not start with it. `reaxctl install --gpus ...` refuses to run while the installed release descriptor is older (exit 12, nothing changed). Without `--gpus` the kit behaves exactly as before.

One miner process (it alone holds the hotkey) sends each decision to the backend with the fewest requests in flight. A backend that fails twice leaves the rotation and returns after two good health checks and a repeat of the reference check. Backends never see the hotkey; they only need a token. Every backend must run the same pinned model and image; the miner and `selfcheck` test each one against the published reference decisions and a mismatch stops the start. Capacity scoring still caps at the pool cap, so more GPUs help up to that cap only. Miner-side rules: subnet repository `docs/MINER.md`, "Several GPUs or machines behind one hotkey".

Supported for **s1-fast and s1-pro** only; the miner refuses a URL list for s1-lite and s1-cpu, and so does the kit.

## Two GPUs on one machine (s1-pro)

```sh
nvidia-smi -L                      # GPU indexes
./reaxctl doctor --pool s1-pro
./reaxctl install --pool s1-pro --mode mainnet --confirm-mainnet --gpus 0,1   # after human approval
./reaxctl selfcheck                # starts both sidecars, one verdict per backend
```

What `--gpus 0,1` does:

| | |
| --- | --- |
| Sidecars | services `runtime` (GPU 0) and `runtime-1` (GPU 1), each reserving only its GPU (`device_ids`, the compose form of `docker run --gpus device=K`; inside the container the GPU is device 0, so no `CUDA_VISIBLE_DEVICES` is needed) |
| Ports | backend *i* is published on `BIND:(pool port + 10·i)`: s1-fast 8101, 8111, 8121 …; s1-pro 8102, 8112, 8122 … |
| Miner env | `REAX_S1_PRO_RUNTIME_URLS=http://127.0.0.1:8102,http://127.0.0.1:8112` (instead of `REAX_S1_PRO_RUNTIME_URL`) |
| Network | each sidecar runs in its own bridge network and is published only on its bind address; the miner stays on the host network. This also keeps each s1-pro sidecar's unauthenticated internal vLLM (:8000) private to its container, so two of them do not clash |
| Startup | the miner waits for every sidecar to be healthy |

Weights are downloaded once and mounted read-only into every sidecar. Each GPU needs the memory the pool requires (s1-pro: 80–96 GB class). The sidecar ports must never be reachable from the internet; the kit only ever binds them to loopback or a private address.

## Options

- `--gpus 0,1,2,3`: GPU indexes, distinct, at most 16. `--no-fanout` goes back to one sidecar on the next `install`.
- `--backend-bind IP`: address the sidecars are published on, default `127.0.0.1`. A loopback or private-network literal (10/8, 172.16/12, 192.168/16, `fc00::/7`) only; `0.0.0.0` and public addresses are refused. A private address is for a setup where the sidecars are reached over a private network; firewall the ports so only the miner machine can connect.
- `--backend-token-files F0,F1`: one existing regular file per GPU (mode 0600, not a link, no `: , |` in the path), distinct. Backend *i* then uses file *i* as its token and the miner list entry becomes `URL|/run/backend-token-i` (the files are mounted into the miner and selfcheck containers). Without the option every backend uses the shared `secrets/runtime-token`.
- The miner's `REAX_ALLOW_PUBLIC_RUNTIME` is deliberately not exposed: public runtimes would send the token in clear text.

Not generated by the kit (set them in `miner.env` yourself if you need them): `REAX_RUNTIME_INFLIGHT`, `REAX_MAX_CONCURRENT`, `REAX_PER_CALLER_CONCURRENCY`, `REAX_PER_CALLER_PER_MINUTE`. The miner multiplies the default limits by the number of backends.

## selfcheck with several backends

`reaxctl selfcheck` starts all sidecars that are stopped, waits until all are healthy, then runs `reax-selfcheck` once against the whole list. `data.backends[]` holds one entry per URL (`pass`, answered/distance/round figures or an `error`) and the summary names each one:

```
Reference self-check passed for all 2 backends. http://127.0.0.1:8102: PASS 640/640 answered; ...; http://127.0.0.1:8112: PASS 640/640 answered; ...
```

If any backend fails, the exit code is 20 and you must not register or mine until every backend passes.

## Hardware pooling note

Several machines work the same way: run the sidecar on each machine (same image, weights and flags as the single-machine sidecar, listening on its private address) and list the URLs in `miner.env`. `reaxctl` renders only one machine; for a multi-machine setup edit `REAX_<MODEL>_RUNTIME_URLS` by hand and use `reax-selfcheck --model <pool>` from the miner image.
